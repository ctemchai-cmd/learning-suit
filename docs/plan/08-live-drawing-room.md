# 08 — ห้องวาดร่วม (Live drawing room)

เพิ่ม 2026-10-02 ตาม feedback: “แชร์ลิงก์แล้ววาดด้วยกันแบบ realtime … Undo ของตัวเอง” (แบบแก้ไขร่วมกันเต็มรูปแบบ)
การตัดสินใจของผู้ใช้: ผู้เรียน **ใส่ชื่อก่อนเข้า**, **ยังแทรกรูปไม่ได้** (เห็นรูปของครูได้), **จัดการสไลด์ได้เฉพาะครู**

## 1. แนวคิด: เครื่องครูเป็นผู้ตัดสิน (host-authoritative)

- ครูกด “วาดร่วม” → “เปิดห้องและสร้างลิงก์” ได้ `/live/<roomId>` (128-bit สุ่ม; ลิงก์คือกุญแจ) ผู้เรียนเปิดลิงก์ ใส่ชื่อ เข้าห้อง ไม่ต้องมีบัญชี
- ทุกการแก้เป็น `DocumentTransaction` เดิม (commands.ts) — ผู้เรียนแสดงผลทันที (optimistic) แล้วส่ง `op` ให้ครู; เครื่องครูตรวจสิทธิ์ (`guestPermission`) + ตรวจรูปแบบ/ขอบเขต (`applyDocumentCommand`) แล้ว commit ลง history ของครู (บันทึกลงเครื่อง + Cloud ตามระบบเดิม) และกระจาย `applied {epoch, seq}` ให้ทุกคนใช้ตามลำดับเดียวกัน
- ผู้เรียนเก็บ `GuestReplica` = ฉบับที่ครูยืนยันแล้ว + การแก้ของฉันที่ยังรอยืนยัน (rebase ทุกครั้งที่มีของใหม่; ที่ใช้ไม่ได้แล้วถูกทิ้ง; ถูกปฏิเสธ = ย้อนเอาออก + แจ้งเหตุผล); เลขลำดับขาดหรือ epoch เปลี่ยน (ครูโหลดหน้าใหม่) = ขอฉบับเต็มใหม่ (`hello` → `snapshot`) แล้วส่งการแก้ที่ค้างอีกครั้ง (ครูกันซ้ำด้วย opId)
- แก้วัตถุเดียวกันพร้อมกัน: อันที่ถึงเครื่องครูทีหลังชนะ (ค่าทั้งชิ้นตาม command เดิม)
- ไม่มีระบบบันทึกใหม่ ไม่มีตารางใหม่ ไม่มีสิทธิ์ฐานข้อมูลสำหรับผู้เรียน — ผู้เรียนไม่แตะ Supabase DB/Storage

## 2. Undo ของใครของมัน (`src/domain/live/selective-undo.ts`)

แต่ละคนมี stack ของตัวเอง (ขั้นละ `{before, after}` ของเอกสาร; Immer แชร์โครงสร้างจึงไม่เปลือง) Undo = คำนวณ transaction ย้อน **เทียบกับเอกสารปัจจุบัน**:
- วัตถุที่ฉันเพิ่ม → ลบ (ถ้ายังอยู่และไม่ล็อก); ที่ฉันลบ → ใส่คืน (ถ้ายังไม่มี); ที่ฉันแก้ → คืนค่าเฉพาะ **ฟิลด์ที่ฉันเปลี่ยน** (คนอื่นย้าย/แก้ฟิลด์อื่นยังอยู่); ล็อก/ปลดล็อก, ลำดับชั้น, สไลด์ (เพิ่ม/ลบ/ชื่อ/พื้นหลัง/ลำดับ), ชื่อบทเรียน แบบเดียวกัน
- ถ้าสิ่งที่ทำถูกคนอื่นเปลี่ยนกลับหมดแล้ว ข้ามไปขั้นก่อนหน้า; Redo = ย้อนสิ่งที่ Undo ทำ; ปุ่ม/⌘Z ระหว่างอยู่ในห้องใช้ stack นี้ (ครูกลับไปใช้ history ปกติเมื่อปิดห้อง ซึ่งรวมการแก้ของผู้เรียนด้วย)

## 3. สิทธิ์ผู้เรียน (`guestPermission`)

ได้: เพิ่ม/แก้/ลบ/จัดลำดับวัตถุบนสไลด์ (ปากกา รูปทรง ข้อความ ตาราง โค้ด ภาพประกอบ ตัวจำลอง) — ไม่ได้: สไลด์ (เพิ่ม/ลบ/ชื่อ/พื้นหลัง/ลำดับ), ชื่อบทเรียน, ล็อก/ปลดล็อก (วัตถุที่ครูล็อกจึงปลอดภัย), แทรกรูป/asset; หนึ่งรายการ ≤ 512 KB; ≤ 25 รายการ/วินาที/คน; UI ปิดปุ่มที่ใช้ไม่ได้ (สไลด์, ล็อก, รูป, บันทึก, Export, เปลี่ยนชื่อ)

## 4. ช่องทางส่งข้อมูล (`src/services/live/transport.ts`)

- Cloud: Supabase Realtime **broadcast** (`live:<roomId>`, self=false) + **presence** (ชื่อ/บทบาท/สี) ใช้ publishable key; ข้อความ > 60 KB แบ่งเป็นชิ้น (ฉบับเต็มของบทเรียน, รูป base64)
- Local (ไม่มี Supabase / e2e): `BroadcastChannel` ระหว่างแท็บ + presence ด้วย heartbeat
- เคอร์เซอร์: ส่ง ≤ ~8 ครั้ง/วินาทีขณะขยับ, ห้องที่มีเกิน 12 คน ผู้เรียนไม่ส่งเคอร์เซอร์ (ประหยัดโควตาข้อความ) — ครูยังส่ง
- รูปของบทเรียน: ผู้เรียนขอ `asset-request` ครูส่งจากเครื่อง (IndexedDB) เป็นชิ้น
- **ตั้งค่า Supabase**: Realtime ต้องยอมให้ public channel (Project Settings → Realtime → ปิด “Private channels only” ถ้าเปิดไว้); โควตาแพ็กเกจฟรีจำกัดจำนวนการเชื่อมต่อพร้อมกันและข้อความต่อเดือน (ตรวจใน dashboard)

## 5. การใช้งาน

- ครู: ปุ่ม “วาดร่วม” (หัว editor) → ลิงก์ + คัดลอก + รายชื่อคนในห้อง + “ปิดห้อง”; ปุ่มแสดง “วาดร่วม · N”; โหลดหน้าใหม่ = ห้องเดิมกลับมาเอง (roomId ใน sessionStorage) ผู้เรียนต่อใหม่อัตโนมัติ; ออกจากหน้าบทเรียน = ห้องหยุดชั่วคราว
- ผู้เรียน: ใส่ชื่อ (จำในเครื่อง) → editor เดียวกับครู สถานะ “ห้องวาดร่วม · แก้พร้อมกันได้”; “ตามครู” (ค่าเริ่มต้นเปิด) เปลี่ยนสไลด์ตามครู; รายชื่อคนในห้อง; ครูไม่อยู่ = อ่านอย่างเดียว “รอครูเชื่อมต่อ…”; ครูปิดห้อง = หน้าจอ “ครูปิดห้องแล้ว”
- เห็นเคอร์เซอร์ + ชื่อของคนอื่นบนสไลด์เดียวกัน

## 6. ข้อจำกัดที่ยอมรับ

- ต้องเปิดเครื่องครูไว้ระหว่างใช้ห้อง (ครูคือผู้ตัดสินและที่บันทึก)
- ใครมีลิงก์ก็เข้าได้และแก้ได้ (ลิงก์เดาไม่ได้, ครูปิดห้องได้ทันที, วัตถุที่ล็อกแก้ไม่ได้)
- แก้ชิ้นเดียวกันพร้อมกัน = คนหลังชนะทั้งชิ้น (ไม่ใช่รวมทีละฟิลด์); ข้อความที่กำลังพิมพ์ในกล่องเดียวกันพร้อมกันจะทับกัน
- ผู้เรียนยังแทรกรูปไม่ได้; Export ปิดสำหรับผู้เรียน
